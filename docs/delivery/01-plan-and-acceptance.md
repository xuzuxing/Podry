# 开发计划与验收

本计划先确定可评审合同与页面，再逐步接入真实后端。M0 原型完成不代表 M1–M5 已实现。

2026-11-20 后端排期补充：当前按 [后端开发计划](../backend/01-development-plan.md) 的 B0–B6 实施，暂不推进前端；先真实 CI/CD 和资源查看，再交付通用资源写入、晋级/回滚等增强。下方 M0–M5 保留为全量路线和验收用例库，不要求先完成旧 M2 才能开发 CI。逐项执行见 [任务清单](../backend/02-task-breakdown.md) 与 [接口分期](../backend/03-api-delivery-matrix.md)。

## 1. 里程碑

| 阶段 | 交付 | 完成门槛 |
| --- | --- | --- |
| M0 | 产品、页面原型、API、数据、架构文档 | 静态引用/合同检查通过，浏览器可走核心交互 |
| M1 | 身份、项目授权、集群接入、资源查看 | 两个集群真实 List/Get/Events；隔离权限实测 |
| M2 | YAML、资源操作、日志与终端 | Dry Run/Diff/Apply、冲突、删除前置条件和越权验证 |
| M3 | Git/Webhook、构建 Job、产物与归档 | 推送生成可拉取 digest；取消、重试、重启恢复 |
| M4 | 环境覆盖、Helm、晋级、回滚 | 同 digest 多环境发布、完整快照回滚、并发与未知结果恢复 |
| M5 | 资源归属、漂移、审计、端到端验收 | 两个业务场景闭环，失败路径有真实证据 |

里程碑按依赖推进，可在 M1 后并行开展 CI 后端与资源 UI，但本计划不构成已验证工期。具体人力和时间在 M0 评审及环境预检后估算。

## 3. 两条演示流程

### A：开发者交付

创建项目内应用 → Git → Build → Base → New Workflow / **Build & Deploy from Source Code** → 同时出现 CI 和 Deploy → 手动或 Push 构建 digest → 开发部署 → 资源树/日志 → 生产晋级 → 历史回滚。自动开发部署必须显式开启且环境策略允许。

### B：运维处理异常

选择集群和 Namespace → 找到异常 Deployment/Pod → 查看事件 → 日志/终端 → 预览并修改配置或重启 → 观察恢复 → 应用漂移与审计。

## 4. 证据级别

| 级别 | 能证明 | 不能证明 |
| --- | --- | --- |
| 文档静态检查 | 链接、Schema 引用、枚举和文件关系 | 真实接口、SQL 可执行、授权安全 |
| 参考实例观察 | 用户部署中实际页面、导航，以及明确记录的测试应用保存/初始构建 | Podry 已实现、最终完整流程已发布、未执行的终端/资源写入、所有版本完全相同 |
| 离线浏览器 | 页面导航和模拟交互可用 | Git、BuildKit、Helm、K8s、真实 WebSocket |
| 后端自动化 | Handler、SQL、状态流与错误分支 | 用户真实环境网络、Registry、集群策略 |
| 集成环境 | 实际构建发布和资源操作 | 生产可用性和业务验收 |
| 用户验收 | 指定目标环境和业务路径得到确认 | 未覆盖场景与全平台完整复刻 |

本次实际记录见 [验证记录](02-validation.md)。正式开发每阶段更新对应证据，不把尚未运行的设计稿标记为完成。

V2 的 M0 额外要求：对照真实截图检查配置/执行入口分离、右侧大抽屉、历史分栏、应用内资源页签、集群资源多页签和 Namespace/集群切换清理。当前用户反馈仍是原型验收依据，自动化通过不等于用户已认可交互。

V2.1 的 M0 增加：从全新应用开始，必须实际走主模板的 CI **与 Deploy** 两步；验证 0/4 引导、分节保存、没有默认 CD、完整创建表单、首次无镜像、Git 读取失败禁用、成功但无归档日志、应用 Job 完成模拟。2026-11-19 真实测试实例的 Git 查询被网络阻塞，发布未执行；2026-11-20 [只读补拍](../references/devtron-onboarding/README.md) 已观察到完整工作流已有构建、部署成功及 Job/Pod 完成。本地离线检查与远程实例观察仍分别记录，不能据此认定 Podry 已具备真实后端交付能力。

## 5. 进入实现前的决策

需在实现开始时核对构建集群、BuildKit worker 模式、Registry、Namespace 授权、Chart/日志保留、敏感配置版本策略。当前统一采用“平台管理的版本化密文引用”作为合同；若改用外部 Secret 管理器，必须同步修改 API、SQL 和回滚验收。
