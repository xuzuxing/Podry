# 后台持续健康巡检

日期：2026-11-21。继续 T22 应用健康观察；真实 CI/CD、集群运行与 B6 验收仍暂缓。

## 行为与启用

默认 `PODRY_HEALTH_POLLING_ENABLED=false`，关闭时不领取任务、不解密凭据、不访问集群。显式开启且配置主密钥后，后台持续刷新绑定健康；不依赖浏览器打开资源页面，也不依赖构建、发布或资源写入 Worker 的开关。三个写执行 Worker 继续默认关闭。

没有新增 HTTP 接口或 DTO 字段。应用详情、列表和 health 筛选继续读取同一 60 秒投影；资源 GET 仍能主动刷新。健康与发布历史分开，发布 succeeded 不能直接生成 healthy。Deployment 与 Job 的完整 UID、固定镜像、执行标签、generation、副本及成功 Pod 规则沿用 [应用资源与健康观察](13-application-observation.md)。本轮不刷新漂移缓存。

巡检针对未归档应用的每个绑定，使用**最近发布请求 requested_by 对应用户的当前身份与权限**。这是管理员开启全局只读巡检后的服务行为，不持久化浏览器 Token，不选择任意高权限成员兜底；账号退出登录不停止其已提交发布的后台观察。停用账号、撤销项目访问或资源 view 授权会阻止观察；授权恢复后下一次重新检查。应用查看者只能看到应用健康摘要，对象内容仍受 resource.view 限制。

未发布、没有记录根资源、最新执行 queued/unknown 时只更新调度，不访问集群。submitting/observing/succeeded/failed 的已知资源仍可观察，但必须由最近执行的工作负载 UID 提供健康事实；缺失身份为 unknown。归档不领取任务，仍投影逻辑 stopped，不执行真实停机。

## 调度、并发与恢复

正式迁移 v17 新增 `binding_health_polls`，共 36 张业务表。升级回填所有绑定，新绑定通过同事务、invoker 权限的 INSERT trigger 创建调度行；没有 SECURITY DEFINER。每绑定一行，保存 next_poll_at、租约 UUID/截止时间、最近开始时间及固定安全错误码，不存资源内容、凭据或健康历史。

- 单进程一个串行巡检循环，空闲每秒扫描；有到期绑定立即继续处理，按 next_poll_at、binding_id 公平排序。多实例通过 FOR UPDATE SKIP LOCKED 领取。
- 租约 45 秒，单步观察预算 25 秒，其中 Kubernetes ReadOwned 预算 20 秒；完成或普通失败后 30 秒重试。负载过高可能超过健康 TTL，此时摘要保守回到 unknown，不延长新鲜度。
- 数据库锁仅覆盖短事务。网络 GET 在事务外执行；复用既有类型过滤、UID 与 OwnerReference、逐对象投影及 Secret 脱敏。不会执行集群写入。
- 写缓存前重验账号、项目成员关系、应用归档、绑定/目标、最近执行 revision、根资源身份、资源授权指纹及凭据版本。项目成员变更与最终缓存提交使用相同团队/项目锁；资源授权最终重验放入缓存事务。
- 调度租约完成与观察缓存同事务提交。租约过期或已被接管，整个旧观察事务回滚；旧 Worker 不能覆盖新状态或新调度元信息。观察时间使用开始网络读取前的数据库时钟，慢读取不会抬高缓存新鲜度；交互读取与租约时间统一时钟，避免应用主机与 PostgreSQL 时钟偏差误删较新缓存。
- 读取失败、撤权、身份变化或全部类型过滤时清除本次领取前的旧缓存；稍后开始的交互查询结果保留。上游失败只记录固定安全错误码，不保存远端响应或原始异常。
- 崩溃、取消或数据库写入失败遗留的租约到期后可重新领取；恢复不依赖内存事件。统一 Runtime drain 停止新领取，已领取步骤使用 work 上下文完成，仍受全局停机 deadline 约束。

v17 降级只删除可重建的调度元数据，保留原有健康缓存、发布与审计；再次升级重新回填。v16 及更早的配置/历史降级保护保持有效，不能靠删除历史绕过。备份恢复包含本表，恢复时先保持所有外部 Worker 与健康巡检关闭，显式核对集群、主密钥和身份后再开启；旧租约正常到期恢复。

## 迁移与服务角色

启动核对干净 v17，不自动迁移。开发数据库本轮未迁移。显式升级命令为：

```powershell
go run ./cmd/podry migrate up
```

在既有最小服务角色授权上增加 binding_health_polls 的 SELECT/INSERT/UPDATE，以及 binding_observations 的 DELETE。INSERT 供新绑定 trigger 使用；DELETE 仅清理失效缓存。其余业务表及不可变历史权限保持原约束。

这些证据不代表真实 Kubernetes Admission/RBAC、生产轮询负载、集群健康或 CI/CD/B6 验收。实际环境恢复后仍需验证轮询容量、网络与权限变化下的持续新鲜度。
