# 应用克隆

日期：2026-11-21。补齐 E04 的应用克隆，通过现有创建接口的可选字段实现，不增加 HTTP 操作、表或迁移。正式数据库版本保持 v11，28 张业务表；OpenAPI 更新至 V1.13.0，仍为 68 implemented / 8 planned。

## 接口与结果

`POST /api/apps` 接收目标应用信息和源应用 ID，成功返回 201 Application：

```json
{
  "projectId": "a1000000-0000-4000-8000-000000000001",
  "name": "podry-demo-copy",
  "description": "克隆后独立维护",
  "sourceMode": "git",
  "cloneFromAppId": "a1000000-0000-4000-8000-000000000002"
}
```

sourceMode 必须与源应用一致，支持 git/image。目标项目、名称和描述取自本次请求。允许从可读取的已归档应用复制配置；新应用未归档，健康状态 unknown。

源应用的最新配置快照复制为目标配置版本 1，保留 Git、Build、Chart、Values 和准确的 Secret 引用；不复制完整配置历史。源应用尚未保存任何配置时，目标也保持虚拟版本 0，不产生空快照行。部分配置同样可以克隆，setup 按实际内容派生，不补造缺失配置。

有 Build 配置时，imageRepository 固定生成为 `podry/<新应用 UUID>`，避免克隆后向源应用仓库推送。克隆不连接 Git、Registry 或 Kubernetes，不解密、复制或轮换凭据。Git 和 Registry 继续引用凭据 ID，运行时 Secret 继续引用源配置指定的准确版本，后续执行仍需按现有流程检查可解密性和可用性。

流水线、环境绑定与覆盖、构建、产物、预览、发布快照、部署记录、运行资源和健康缓存均不复制；workflowVersion=0。镜像应用同样不复制已有产物，用户需另行导入镜像。创建完成后可读取 config/setup，审阅配置并创建工作流；创建操作不触发构建或发布。

## 权限与事务

- 源项目需要读取权限，viewer 可读；目标项目需要 configure 权限，即 admin/developer。无权访问的源应用或项目返回 404，目标仅有 operator/viewer 时返回 403。
- 配置中的 Git、Secret 和间接 Registry 凭据引用，分别按源应用与目标项目的团队作用域检查。即使用户同时属于两个团队，也不能把团队专用凭据带入另一团队；失败返回 404，不静默删减配置或扩大授权。平台级可引用凭据按既有权限规则处理。
- UUID、名称或 sourceMode 不合法返回 422；引用类型及配置约束沿用配置保存校验。源应用或引用不存在返回 404。同一项目内应用名称重复返回 409。
- 锁定当前用户后，按稳定顺序先锁定涉及的全部团队，再锁定全部项目，重验双方权限，最后锁定源应用并读取最新快照。与配置保存、成员变更保持锁顺序，避免相反方向跨项目克隆的死锁；等待锁期间发生撤权时按最新权限拒绝。
- 新应用、配置快照和 `application.create` 审计在同一数据库事务内提交。审计记录新增 cloneFromAppId 和 sourceConfigVersion，只记录引用与来源，不写凭据明文。任何校验或写入失败都会回滚，不留下半创建应用。

本接口沿用普通应用创建语义，没有 Idempotency-Key 重放合同。网络响应丢失后应先查询目标项目中的应用；使用同名直接重试会得到 409。跨项目克隆不隐式创建团队成员、资源 grant 或环境绑定。
