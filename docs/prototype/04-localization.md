# 中文研发团队交互适配

日期：2026-11-20。本轮基于用户“可以适当考虑国情”的反馈，调整中文术语、页面布局与日常操作路径。以中文研发团队的可读性为目标，不继续逐页照搬 Devtron。

## 本轮调整

| 场景 | 交互决定 |
| --- | --- |
| 全局导航 | 桌面使用带中文名称的窄侧栏；小视口折叠图标；保留当前栏目和键盘聚焦反馈 |
| 应用列表 | 常驻项目、状态筛选；中文列名；显式提供“构建发布”和“配置”入口 |
| 构建发布 | 左侧展示代码与镜像构建，右侧按环境展示发布目标、集群、命名空间和状态，减少流程画布占用 |
| 流水线配置 | 保留源代码 → 构建 → 部署的关系图，用于维护一 CI、多环境 CD；与日常操作页面分工 |
| 创建与编辑 | 新建应用使用居中弹窗；简单流水线编辑缩小抽屉并移除无操作意义的侧栏和未实现页签 |
| 发布确认 | 使用“选择镜像 → 发布预览 → 确认发布”；发布、回滚、跨环境发布继续保留名称确认 |
| 集群资源 | 资源分类、状态、工具栏中文化；中文名称旁保留 Pod、Deployment 等原生 Kind |
| 时间与状态 | 统一简体中文、24 小时时间；状态显示中文，接口枚举、资源名和 YAML 不翻译 |

不把“本土化”扩展为新增审批、企业微信/钉钉、Gitee、国内镜像源或合规能力。这些需要单独定义接口和运行环境；本轮不新增无实现的入口。

## 组件与数据边界

- `PrototypeApp`：导航外壳；按视口折叠，不新增业务状态。
- `ApplicationList`：应用筛选与路由；复用既有创建接口。
- `DeliveryWorkbench`：展示构建上下文与环境列表；props 输入状态，emits 发起构建、发布和查看记录；无请求与轮询。
- `WorkflowCanvas`：保留业务编排、模板和执行抽屉；执行页组合 DeliveryWorkbench，配置页组合 WorkflowNode。
- `utils/display.ts`：集中中文状态、环境显示名、资源类型和时间格式；不改变接口枚举及资源身份。
- 既有配置、历史与资源组件：替换面向用户的术语，保留 DTO、Hash 路由、确认与 Mock 校验。

## 验证范围

最终独立构建上的 27 项业务检查和 6 项交互反馈检查均已通过，覆盖中文导航与筛选、新建应用、完整源码构建并部署、环境发布入口、回滚与跨环境发布、资源页签与变更确认、只读和异常、键盘与减少动态效果、1024px / 390px 布局。另已单独验证镜像来源应用创建后直接进入部署模板，接口仍使用原始 image 枚举。

原型与普通产品入口构建均已通过。完整结果见 [验证记录](../delivery/03-vue-validation.md)、[业务检查报告](../delivery/vue-prototype-check.json) 和 [交互反馈报告](../delivery/vue-feedback-check.json)。上述检查使用本地 MSW 数据，不等同真实后端或集群验收，也不代表用户已认可视觉设计。
